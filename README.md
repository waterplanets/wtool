# wtool

> RPG Maker 游戏的嵌入式实时翻译工具 —— 不用改游戏本体，把译文直接送进游戏窗口。

wtool 面向已经拿到**译文词典**、想让游戏当场以中文跑起来的玩家与译者。它把翻译
通道嵌进游戏进程：游戏照常渲染文字，只是画出来的时候已经是译文。词典来自哪里不
重要 —— MTool 的 `TrsData.json`、wtool 自己的格式，或者你用 wtool 的离线翻译现
翻出来的都行。

支持 **RPG Maker MZ / MV / RGSS3（VX Ace）** 三类引擎。

## 特性

- **两种注入形态，三个引擎都有**
  - **实时连接**：游戏运行时连着 wtool，词典和字体都在 wtool 手里，改一下立刻重
    下发生效 —— 调字体、试词典时用这条。代价是玩的时候 wtool 得开着。
  - **一次性注入**：安装时把词典和字体烤进游戏侧文件，**装完即终态**，游戏自己查
    表，wtool 关掉也照翻 —— 正式玩的时候用这条。
- **零注入的 RGSS3 方案**：走游戏自带的松散脚本 `Patch/Patch.rb`，不动进程内存、
  不落 DLL、不碰杀软敏感操作，删文件即撤销。
- **词典格式互通**：读 MTool 词典 / wtool 行式文本（TSV）/ wtool JSON；三种都能
  写出，也能互相转换。TSV 可排序、可 diff、能手改。
- **离线翻译**：把游戏扫成"语料"，再用 Google gtx（免费零配置）或任意 OpenAI 兼
  容接口（DeepSeek、GPT 等）翻成词典。断点续传，翻一半停下来下次接着翻。
- **智能查表**：整段精确 → 单行精确 → 最长片段替换三级退级，并内置战斗日志的消
  息模板兜底，控制码（`\c[2]`、`\i[127]`、`\v[n]`）原样保留。

## 支持的引擎与注入方式

| 引擎 | 运行时 | 实时连接 | 一次性注入 |
| --- | --- | --- | --- |
| RPG Maker MZ | NW.js | JS 插件桥（TCP 连 wtool） | 烤入插件（词典随插件走） |
| RPG Maker MV | NW.js | JS 插件桥（TCP 连 wtool） | 烤入插件（词典随插件走） |
| RPG Maker VX Ace（RGSS3） | 原生 | 文件轮询热重载（`Patch/`） | NWPatch / `Patch.rb` 烤入 |

> MV 与 MZ 共用同一套 NW.js 插件机制，界面里按你的游戏目录自动识别。

## 快速开始

### 直接使用（发布版）

1. 打开 wtool，在「翻译」页选游戏目录（就是含 `Game.exe` 的那层）。
2. 选一份词典（MTool 的 `TrsData.json` 或 wtool 词典），需要的话指定目标字体。
3. 按页面提示选注入模式，点主按钮。实时模式记得让 wtool 一直开着。

### 从源码构建

前置：Node.js 18+、Rust 稳定版工具链、以及 [Tauri 2 的系统依赖](https://tauri.app/start/prerequisites/)。

```bash
npm install
npm run tauri dev     # 开发
npm run tauri build   # 打包
```

只跑前端类型检查与构建：`npm run build`；只检查 Rust：`cd src-tauri && cargo check`。

## 使用流程

「翻译」页是主流程（选游戏 → 选词典 → 开始），其余页面是给它准备素材和善后：

- **采集语料**：不在游戏里跑，直接扫游戏目录，把所有待翻原文收成一份语料。
- **离线翻译**：语料 → 词典。选后端（gtx / LLM）、填输入输出，可以反复跑、断点续传。
- **词典与格式**：词典另存为、换格式、导出 MTool 兼容格式、查看词表。
- **高级**：手动装 / 卸某条注入方式，生成常驻主机启动脚本，查看各类文件位置。

## 词典与格式

wtool 认识三种文件，靠**内容**自己认，不看文件名：

| 格式 | 长相 | 说明 |
| --- | --- | --- |
| MTool 词典 | 扁平 JSON `{"原文":"译文"}` | 社区通用格式；能读，也能**显式导出** |
| wtool 行式文本 | `原文<TAB>译文`，带 `#wtool-tsv 1` 头 | 可排序、可 diff、能手改 |
| wtool JSON | `{"wtool":1,"entries":{...}}` | 带版本标记，将来可演进 |

转义规则（TSV 与 JSON 一致）：`\\` `\t` `\n` `\r`。空译文按"未翻译"处理，不会
写进文件。

MTool 词典是**外部契约**：wtool 默认只拿它来读，只有你在"输出格式"里主动选了
MTool，才会写出一份扁平的、MTool 能读回去的 JSON。加密的 MTool 文件（开头
`99 99 99`）wtool 读不了，请在 MTool 里导出明文再试。

## 目录结构

```
src/                  Vue 3 前端（页面、store、Tauri 调用封装）
src-tauri/src/
  engine/             引擎适配与注入方式（mz / rgss3 / inject）
  dict/               词典：格式嗅探、MTool 适配、wtool 读写
  corpus/             语料：离线扫描、RGSS3 归档解析
  translate/          翻译后端（gtx / OpenAI 兼容）
  task.rs             后台任务主循环
  commands.rs         前端可调用的命令
src-tauri/resources/  注入到游戏侧的插件 / 脚本模板
```

## 文件都放在哪

| 东西 | 位置 |
| --- | --- |
| 配置 | `%APPDATA%\wtool\config.json`（API Key 明文，仅本机；也可用环境变量 `WTOOL_LLM_KEY`） |
| 常驻主机日志 | `%APPDATA%\wtool\host.log` |
| 游戏侧翻译日志 | 游戏目录下 `wtool.log` / `wtool.1-4.log`，**取消注入时会一并清掉** |
| 游戏侧注入产物 | 游戏目录内（`js/plugins/`、`Patch/` 等），取消注入时还原 / 删除 |

## 常见问题

**gtx 翻译连不上？**
`translate.googleapis.com` 在国内直连通常不通。设置环境变量 `HTTPS_PROXY` 后再启
动 wtool，或改用 LLM 后端。

**装了但游戏里没反应？**
先确认注入模式：实时模式需要 wtool 开着；一次性模式装完要重启游戏。再看「高级」
页里那条方式的状态是不是 `installed`，以及底部日志有没有报错。RGSS3 与 MV/MZ 动
态拼接的文本（部分技能/物品说明）受引擎限制，可能翻不到。

**游戏里的图（CG、图片字）能翻吗？**
不能。wtool 只处理文字绘制；画在图片里的台词、`gallery-*` 之类的图片素材需要另
用图像工具处理。

**会不会污染游戏目录？**
一次性注入会往游戏目录放文件，取消注入时清理；实时模式退出即卸。日志见上表。
